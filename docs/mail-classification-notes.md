# 予定の判定メモ

## 12月の航空券を見つけた手順

11月の受信箱785件に範囲を広げ、件名の「航空券予約確認書」を手掛かりに本文で12月の旅程を確認した。支払い完了メールには発券後に確認メールを送ると書かれていたため、同じ送信元の後続メールを検索した。件名に日付のない「eチケットや旅程表」に発券情報と各区間のステータス `OK` があった。

実装時は、支払い・予約受付・発券済みを区別し、同じ旅程の後続通知で状態を確定する。旅程は区間ごとに抽出し、空港コードから出発地と到着地それぞれの現地時間を扱う。到着時刻の `+1` は翌日として扱う。発券日と搭乗日を区別し、予約確認書と発券通知に載った同じ便は一つにまとめる。

## 新着から予定を見つけた手順

2026年11月21日、Yahoo!メールの受信箱の新着75件の件名を確認し、予定や期限に見えるメールの本文を照合した。Shoppingの新着も件名を確認した。サーバー側のキーワード検索は使っていない。

| 件名・本文で見た手掛かり                                                       | 判断                                                                                                                                                    |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 「会場と当日スケジュールのご案内」→「参加者各位」、日時、会場、当日の進行      | 参加者向けの確定案内。「受付開始」と「イベント開始」を区別し、イベント開始から終了予定までを登録候補にする。会場住所が東京なら現地時間は `Asia/Tokyo`。 |
| 「日程調整が確定しました」→本人が参加者、`11/24(火) 13:00 - 13:45 (Etc/GMT-9)` | 確定した面接。年は受信日と曜日から2026年と判断。`Etc/GMT-9` は UTC+09:00。                                                                              |
| 「請求額確定」、請求対象月                                                     | 請求額の確定。対象月を支払日・対応期限として扱わない。                                                                                                  |
| `Planned Change`、作業時間、`No action is required`                            | 事業者側の作業通知。このメールには本人の対応予定がない。                                                                                                |
| 開催日や締切付きのセール・参加募集                                             | 一般向け案内。本人の参加確定や対応義務が確認できるかを本文で判断する。                                                                                  |

実装時は、件名の語句を本文を確認するための手掛かりに使う。本文では「誰の予定か」「何が確定したか」「日時が何を指すか」「時差の根拠は何か」を別々に確認する。年のない日付は受信日と曜日を照合し、登録前に未来日時・後続の変更や取消・既存カレンダーとの重複を確認する。
